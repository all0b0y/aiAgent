# 📖 Терминология

> [!abstract] Как пользоваться
> Держи открытым рядом с курсом. Термины сгруппированы по темам, внутри — по алфавиту. В скобках — английский оригинал: в документации и сообществе используют именно его. 🟢 — нужно знать с первого дня, 🟡 — когда начнёшь строить, 🔴 — продвинутое.

---

## 🧠 Модели (LLM)

| Термин | Что это простыми словами |
|--------|--------------------------|
| 🟢 **LLM** (Large Language Model) | Большая языковая модель. Программа, которая по тексту предсказывает следующий кусочек текста. Claude, GPT, Gemini, Qwen — всё это LLM. |
| 🟢 **Токен** (token) | Единица текста для модели: часть слова, слово или знак. Цена, лимиты и скорость считаются в токенах. По-английски ~4 символа на токен, по-русски обычно дороже. |
| 🟢 **Окно контекста** (context window) | Максимум токенов, которые модель видит за один вызов: инструкции + история + файлы + ответ. |
| 🟢 **Промпт** (prompt) | Текст, который получает модель. В агентах это обычно системный промпт + сообщения + результаты инструментов. |
| 🟢 **Системный промпт** (system prompt) | Постоянные инструкции «над» диалогом: роль, правила, стиль. Пользователь его обычно не видит. |
| 🟢 **Галлюцинация** (hallucination) | Уверенно выданная неправда. Следствие того, что модель продолжает текст правдоподобно, а не проверяет факты. |
| 🟡 **Дата отсечения знаний** (knowledge cutoff) | Момент, до которого собраны данные обучения. О более поздних событиях и версиях библиотек модель не знает. |
| 🟡 **Temperature / top-p / top-k** | Параметры случайности выбора следующего токена. У современных «думающих» моделей их обычно лучше не трогать. |
| 🟡 **Рассуждение** (reasoning / thinking) | Скрытый «черновик», который модель пишет перед ответом. Улучшает сложные задачи, стоит токенов и времени. |
| 🟡 **Effort / reasoning_effort** | Ручка глубины рассуждения: low / medium / high / max. |
| 🟡 **Structured output** | Режим, в котором модель гарантированно отвечает JSON по заданной схеме. |
| 🟡 **Few-shot** | Несколько примеров «вход → правильный выход» в промпте. Модель копирует паттерн. |
| 🟡 **Префилл** (prefill) | Дописать начало ответа за модель. У новых моделей Claude на последнем ходе не поддерживается. |
| 🟡 **RLHF** | Дообучение модели на оценках людей; делает её «помощником», а не просто продолжателем текста. |
| 🔴 **Distributional convergence** | Склонность модели выбирать самый вероятный, «средний» вариант. Причина шаблонного дизайна и текстов. |
| 🔴 **Context rot** (гниение контекста) | Падение качества при росте длины контекста — задолго до его заполнения. |
| 🔴 **Lost in the middle** | Информацию в середине длинного контекста модель замечает хуже, чем в начале и в конце. |

## 🤖 Агенты

| Термин | Что это |
|--------|---------|
| 🟢 **ИИ-агент** (AI agent) | Модель в цикле с инструментами: сама решает, какое действие сделать следующим, видит результат и продолжает до готовности. |
| 🟢 **Агентный цикл** (agent loop) | «Вызов модели → выполнение инструмента → результат в контекст → снова модель». Ядро любого агента. |
| 🟢 **Инструмент** (tool) | Функция, которую модель может «попросить» вызвать: прочитать файл, выполнить команду, поискать в сети. Модель видит имя, описание и схему параметров. |
| 🟢 **Tool call / function calling** | Структурированная просьба модели вызвать инструмент с аргументами (JSON). Выполняет её код, а не модель. |
| 🟢 **Харнесс** (harness) | Всё, кроме модели: цикл, инструменты, права, управление контекстом, интерфейс. Claude Code, Codex CLI, Cursor, Hermes — харнессы. |
| 🟢 **Агентный CLI** | Агент в терминале для работы с кодом: Claude Code, Codex CLI, Gemini CLI, OpenCode. |
| 🟡 **Workflow** | Цепочка вызовов LLM по заранее прописанному коду пути. Предсказуемее и дешевле агента. |
| 🟡 **Оркестратор** (orchestrator) | Агент, который делит задачу и раздаёт части другим агентам. |
| 🟡 **Сабагент** (subagent) | Отдельный агент со своим чистым контекстом; получает задачу, возвращает только итог. |
| 🟡 **Human-in-the-loop** | Человек подтверждает или правит действия агента в важных точках. |
| 🟡 **Режим плана** (plan mode) | Агент только исследует и пишет план, ничего не меняя. |
| 🟡 **Режимы разрешений** (permission modes) | Какие действия агент делает без спроса: всё спрашивать / авто-правки / автономный режим. |
| 🟡 **Песочница** (sandbox) | Изолированная среда (контейнер, VM), где агенту нельзя навредить системе. |
| 🟡 **Git worktree** | Вторая рабочая копия репозитория на другой ветке. Позволяет параллельно запускать агентов без конфликтов. |
| 🔴 **Мультиагентная система** | Несколько агентов, взаимодействующих ради одной задачи. Дорого (~15× токенов чата); оправдано для ценных задач. |
| 🔴 **Generator–verifier** | Один агент делает, другой проверяет. Ревьюер без общего контекста находит больше ошибок. |
| 🔴 **Ralph-цикл** (Ralph loop) | Один и тот же промпт в бесконечном цикле, каждый раз с чистым контекстом; состояние живёт в файлах и git. |
| 🔴 **Stateless reducer** | Агент как функция `(состояние, событие) → новое состояние`. Легко тестировать и возобновлять. |
| 🔴 **Smart friend** | Дешёвая модель работает и в трудный момент консультируется с дорогой. |

## 📚 Контекст и память

| Термин | Что это |
|--------|---------|
| 🟢 **Контекст-инжиниринг** (context engineering) | Управление тем, что попадает в окно модели на каждом шаге. Главный навык при работе с агентами. |
| 🟢 **AGENTS.md** | Открытый формат «README для агентов»: команды, конвенции, структура проекта. Читают Codex, Cursor, Gemini CLI и др. |
| 🟢 **CLAUDE.md** | То же для Claude Code. Можно сделать `@AGENTS.md`-импорт, чтобы не дублировать. |
| 🟡 **Compaction** (сжатие) | Автоматический пересказ истории, когда контекст подходит к лимиту. Теряет детали. |
| 🟡 **Handoff** | Документ передачи работы новой сессии: цель, сделанное, состояние, решения, следующий шаг. |
| 🟡 **Just-in-time context** | Держать в контексте указатели (пути, ссылки), а содержимое подгружать инструментами по мере нужды. |
| 🟡 **Progressive disclosure** (прогрессивное раскрытие) | Знания «этажами»: краткое описание всегда, детали по требованию. Основа скиллов. |
| 🟡 **RAG** (Retrieval-Augmented Generation) | Найти релевантные документы и подставить их в промпт перед ответом. |
| 🟡 **Prompt caching** | Провайдер кэширует неизменное начало промпта — дешевле и быстрее. Не ставь в начало меняющиеся данные. |
| 🟡 **llms.txt** | Файл на сайте документации с её оглавлением/текстом для LLM. |
| 🔴 **Ubiquitous language** (общий язык) | Глоссарий терминов проекта (DDD), общий для людей, агента и кода. Сокращает многословие агента. |
| 🔴 **ADR** (Architecture Decision Record) | Короткая запись архитектурного решения: контекст, решение, последствия. |

## 🧩 Скиллы и расширения

| Термин | Что это |
|--------|---------|
| 🟢 **Скилл** (skill, Agent Skill) | Папка с `SKILL.md` (метаданные + инструкции) и, опционально, `scripts/`, `references/`, `assets/`. Открытый формат agentskills.io. |
| 🟢 **SKILL.md** | Главный файл скилла: YAML-шапка (`name`, `description`) + markdown-инструкции. |
| 🟡 **Описание скилла** (description) | Текст, по которому агент решает, активировать ли скилл. Висит в контексте всегда. «Что делает + когда использовать». |
| 🟡 **Model-invoked skill** | Скилл, который агент вызывает сам, когда задача совпала с описанием. |
| 🟡 **User-invoked skill** | Скилл, вызываемый только вручную (`/name`). Не тратит контекст модели. |
| 🟡 **Slash-команда** | Вызов скилла/команды через `/name` в агентном CLI. |
| 🟡 **Критерий готовности** (completion criterion) | Проверяемое условие в конце шага: как агент поймёт, что шаг сделан. |
| 🔴 **Ведущее слово** (leading word) | Ёмкое понятие из «знаний» модели (*tracer bullet*, *red/green*), которое одним словом задаёт целое поведение. |
| 🔴 **No-op** | Инструкция, которую модель и так выполняет по умолчанию. Тратит контекст впустую — удалять. |
| 🔴 **Premature completion** | Агент объявляет шаг готовым, не доделав. Лечится чёткими критериями и проверками. |
| 🔴 **Скилл-роутер** | Ручной скилл, который перечисляет другие скиллы и подсказывает, какой когда брать. |
| 🟡 **Хук** (hook) | Команда, которую харнесс запускает автоматически на событие (перед вызовом инструмента, после правки, при остановке). Гарантия, а не просьба. |
| 🟡 **PreToolUse / PostToolUse / Stop** | События хуков: перед инструментом (можно заблокировать), после него (линтер), при попытке завершить (можно не отпустить). |
| 🟡 **Exit code 2** | В хуках Claude Code — сигнал «заблокировать». Код 1 не блокирует. |
| 🟡 **Плагин** (plugin) | Пакет из скиллов, сабагентов, хуков и MCP-серверов, ставится одной командой. |
| 🟡 **Маркетплейс** (marketplace) | Каталог плагинов, обычно git-репозиторий. |
| 🟡 **Output style** | Набор инструкций о тоне и формате всех ответов сессии. |

## 🔌 Инструменты и интеграции

| Термин | Что это |
|--------|---------|
| 🟢 **MCP** (Model Context Protocol) | Открытый протокол подключения агентов к внешним системам. «USB-C для ИИ». |
| 🟡 **MCP-сервер / клиент / хост** | Сервер даёт инструменты и данные; клиент — подключение внутри хоста (Claude Code, Cursor…). |
| 🟡 **Tools / Resources / Prompts** | Три примитива MCP: действия, данные для чтения, шаблоны промптов. |
| 🟡 **stdio / Streamable HTTP** | Транспорт MCP: локальный процесс или удалённый сервер по HTTP. |
| 🟡 **JSON Schema** | Формат описания структуры данных; так описывают параметры инструментов. |
| 🟡 **Пространство имён** (namespacing) | Префиксы в именах инструментов (`github_…`, `jira_…`), чтобы модель не путала похожие. |
| 🟡 **Poka-yoke** | Защита от ошибок через устройство инструмента (например, только абсолютные пути). |
| 🔴 **Code mode / code execution with MCP** | Агент пишет код, который сам вызывает инструменты и фильтрует данные; в контекст попадает только итог. |
| 🔴 **Agent SDK** | Библиотека для встраивания агента в свой продукт (Claude Agent SDK, OpenAI Agents SDK). |

## 🛡️ Безопасность

| Термин | Что это |
|--------|---------|
| 🟢 **Prompt injection** | Внешний текст (сайт, письмо, issue) содержит инструкции, и агент выполняет их как твои. |
| 🟡 **Смертельная триада** (lethal trifecta) | Приватные данные + недоверенный контент + канал наружу = риск утечки. Разрывай хотя бы одно звено. |
| 🟡 **Эксфильтрация** (exfiltration) | Вынос данных наружу (HTTP-запрос, письмо, картинка по URL с данными в адресе). |
| 🟡 **Allowlist / denylist** | Список разрешённого / запрещённого (команды, домены, пути). |
| 🟡 **Принцип минимальных прав** (least privilege) | Агенту — только доступы, нужные для задачи. |
| 🟡 **Guardrails** | Ограничители: проверки входа/выхода, хуки, политики. |

## ✅ Качество

| Термин | Что это |
|--------|---------|
| 🟡 **Evals** | Набор тестовых задач и проверок для агента/промпта. Без них изменения — гадание. |
| 🟡 **LLM-as-judge** | Модель оценивает результат по рубрике. Для того, что нельзя проверить кодом. |
| 🟡 **Траектория** (trajectory) | Полная последовательность шагов и вызовов агента в задаче. |
| 🟡 **Трейсинг** (tracing) | Запись траекторий, токенов, времени и ошибок для анализа. |
| 🟡 **Регрессия** | Ухудшение после изменения промпта/модели/кода. |
| 🟡 **Backpressure** (противодавление) | Автоматические проверки (типы, тесты, линтер), которые отклоняют плохую работу агента. |
| 🟡 **TDD / red-green-refactor** | Сначала падающий тест, потом код до зелёного, потом рефакторинг. |

## 🛠️ Процесс разработки с ИИ

| Термин | Что это |
|--------|---------|
| 🟢 **Вайбкодинг** (vibe coding) | Разработка через описания на естественном языке; изначально — «принимаю, не глядя». |
| 🟡 **Агентная инженерия** (agentic engineering) | Зрелая версия: человек проектирует среду, проверки и процесс, агент пишет код. |
| 🟡 **Grilling** (допрос) | Агент задаёт тебе вопросы по одному до полного понимания задачи — перед кодом. |
| 🟡 **Spec-driven development** | Спецификация — источник правды; код выводится из неё. |
| 🟡 **Tracer bullet** | Первый тонкий сквозной срез через все слои, чтобы проверить архитектуру. |
| 🟡 **Вертикальный срез** (vertical slice) | Задача, которая проходит через все слои и даёт работающую пользовательскую функцию. |
| 🔴 **Глубокий модуль** (deep module) | Простой интерфейс, много функциональности внутри. Понятен агенту по интерфейсу. |

## 🎨 UI/UX

| Термин | Что это |
|--------|---------|
| 🟢 **UI / UX** | Интерфейс (как выглядит) / опыт (насколько удобно решить задачу). |
| 🟡 **Дизайн-система** | Токены + компоненты + правила, по которым строится весь интерфейс. |
| 🟡 **Дизайн-токены** (design tokens) | Именованные значения: цвета, шрифты, отступы, радиусы (`primary: #C2410C`). |
| 🟡 **DESIGN.md** | Открытый формат Google Stitch: токены (YAML) + обоснование (markdown) для агентов. |
| 🟡 **PRODUCT.md** | Описание аудитории, задачи, контекста и голоса продукта (подход Impeccable). |
| 🟡 **shadcn/ui, Radix, Tailwind** | Популярный стек: копируемые компоненты на доступных примитивах + утилитарный CSS. |
| 🟡 **WCAG / a11y** | Стандарты доступности / доступность (контраст, клавиатура, скринридеры). |
| 🟡 **Empty / loading / error states** | Пустое, загрузочное и ошибочное состояния экрана — проектируются вместе с основным. |
| 🔴 **AI slop** | Узнаваемый шаблонный «ИИ-дизайн»: Inter, фиолетовые градиенты, карточки в карточках. |
